# 扫描向量浪涌约束 · 闭环加载顺序全局裁决 + 缓变加载

芯片量产测试时，多个扫描向量若按文件顺序加载，瞬间同时置高的引脚可能越过电源浪涌限额。
本工具提供两种相互独立的能力：

1. **闭环加载顺序全局裁决**（既有能力，语义不变）：录入/导入 **向量、每个引脚的整数浪涌
   权重、浪涌限额**，**完整比较全部 n! 条闭环顺序**，生成可执行的加载顺序并逐跳展示明细。
2. **缓变加载**（新增）：量产设备必须遵循已备案的向量编号顺序时，在既有录入/导入模型旁
   启用，**严格按当前录入顺序**执行，为每个正式跳转插入经完整比较的切换暂态，使每个正式
   向量仍在原掩码处采样。

纯静态站点，无后端、无外部依赖。

## 问题模型（闭环裁决）

- 向量数量 `4 ≤ n ≤ 12`，所有向量使用同一 `8–20` 位二进制掩码（自左向右为 `P1 … Pk`）；
- 设备从 **全零安全态** 出发，每个向量恰好执行一次，最后 **回到全零态**；
- 一跳的浪涌 = 该跳中 **由 0 变 1** 的引脚权重之和（1→0 不计浪涌，保持 1 不重复计费），
  要求每一跳浪涌 `≤ 限额`；
- 裁决规则（两级，全局）：
  1. 先取 **全程翻转位数**（0→1 与 1→0 都算翻转，含收尾回零跳）最小的闭环顺序；
  2. 翻转位数并列时，取 **向量编号序列字典序**（编号字符串码点序，故 `10 < 2`）最小者；
- **禁止以逐跳最小翻转（贪心）替代全局裁决。**

## 缓变加载（soft-start）

量产设备有时必须遵循已备案的向量编号顺序，不能由闭环裁决重排。此时在既有录入/导入模型旁
启用缓变加载，并填写 **每个切换阶段最多可同时置高的引脚数**（新上限，1–20）：

- 系统按 **当前录入顺序** 从全零出发，逐向量执行，最终回零；每个正式向量仍在 **原掩码处采样**；
- 每次正式跳转前可插入仅用于切换的暂态：**先一次性完成所有降位**（1→0，不计浪涌），
  **再把待置高引脚分组**依次置高；
- 每组（每个切换阶段）同时满足：**组内引脚权重和 ≤ 既有浪涌限额** 且 **引脚数 ≤ 新上限**；
- 裁决规则（对每个正式跳转完整比较，**不以逐引脚或贪心装箱代替全局裁决**）：
  1. 先取 **插入暂态总数最少** 的方案；
  2. 同数按 **各阶段置高引脚的 P 序列字典序** 取最小。

### 暂态计数语义

一跳经若干切换阶段抵达正式掩码（采样点），**插入的仅切换暂态数 = 切换阶段数 − 1**：
无降位且一组直达 → 0；无降位分 k 组 → k−1；有降位再分 k 组 → k；纯降位 → 0。
降位贡献对分组方案是常数，故“插入暂态最少”等价于“置高分组数最少”。

### 算法：迭代加深 + 字典序惰性枚举（精确等价于全分组比较）

对每个正式跳转的待置高引脚集合 R（≤ 20 个）：

- 从 **可容许下界**（引脚数、权重和、装箱下界，绝不高估）开始逐层加深组数 k；
- 每层按 **P 序列字典序** 惰性枚举可行分组做深度优先搜索，首个成功方案即
  “组数最少且字典序最小”——这是对该跳 **全部分组及其阶段顺序** 的完整比较；
- 失败状态记忆（残集 × 剩余组数）只做剪枝，不影响完备性；
- 各跳分组彼此独立，逐跳最优即全链路最优（同数并列由最先发生的跳转决定）。

测试中另用一份 **完全独立的暴力枚举**（整数掩码子集 + 迭代加深，不共享分组逻辑）
对拍 m=1..9 共 800 组随机用例的最少组数与字典序。

### 失败原因定位

- **单引脚权重大于限额**：该引脚在任何切换阶段置高都会超限，定位到具体正式跳转与引脚；
- **约束下无法分组**：待置高引脚无法在“每组权重和 ≤ 限额 且 引脚数 ≤ 上限”下完成完整分组。

## 页面功能

- 掩码位数、限额、每个引脚权重、各向量编号/掩码的表格录入；
- **缓变加载参数区**：每阶段置高引脚数上限（1–20），与闭环裁决相互独立；
- 文本导入/导出（`PINS` / `LIMIT` / 可选 `MAXP` / `W`(或 `WEIGHTS`) / `编号 掩码`，
  支持 `#` 注释），导入错误按 **源文件行号** 定位；录入错误定位到具体向量行/引脚/上限；
- 「执行全局裁决」做既有闭环裁决；「执行缓变加载规划」按录入顺序出暂态方案，
  均在 Web Worker 中计算；
- 缓变结果按正式跳转展示 **暂态前/后掩码、置高引脚（含权重）、浪涌/限额、采样点、
  本跳插入暂态数与累计暂态数**；
- 无解/无法分组时明确告知并定位原因；
- **任一编辑（含修改上限）立刻撤下旧报告**：顶部出现「输入已变更」提示，在途结果自动作废。

## 本地运行（无需 Docker）

任意静态服务器即可，例如：

```bash
npx serve .                # 或：python3 -m http.server 8080
# 打开 http://localhost:8080
```

## Docker / Docker Compose

```bash
# 构建并启动（宿主机端口可用 WEB_PORT 配置，默认 8080）
WEB_PORT=9090 docker compose up --build -d
# 健康检查：容器内 wget /healthz；编排据 healthcheck 判定 web 健康
curl http://localhost:9090/healthz      # -> ok

# verify 服务：代码测试 + 构建检查 + HTTP 冒烟，自行退出，退出码即结论
docker compose run --rm verify

# 一条命令：起站、跑 verify、verify 结束后整体退出并透传其退出码
docker compose up --build --abort-on-container-exit --exit-code-from verify
```

`verify` 服务依次执行：

1. `node --test test/solver.test.mjs test/softstart.test.mjs` —— 闭环 n! 对拍 + 缓变分组对拍；
2. `node scripts/build-check.mjs` —— 文件齐备性、JS 语法、资源引用、闭环与缓变端到端求解；
3. `BASE_URL=http://web:80 node test/smoke.mjs` —— 针对运行中容器的 HTTP 冒烟。

全部通过退出码 `0`，任一失败非 `0`。

## 不使用 Docker 时的校验命令

```bash
node --test test/solver.test.mjs test/softstart.test.mjs   # 代码测试（需 Node >= 20）
node scripts/build-check.mjs                               # 构建检查
BASE_URL=http://localhost:8080 node test/smoke.mjs
node scripts/find-greedy-trap.mjs  # 重新搜索“贪心 != 全局最优”的固化用例
```

## 导入文件格式

```
# 注释
PINS 8
LIMIT 6
MAXP 2                 # 可选：启用缓变加载，每阶段最多同时置高 2 个引脚（1–20）
W 2 1 3 1 2 1 1 1        # P1..P8 的浪涌权重（也可写作 WEIGHTS）
V1 00101010
V2 11000001
V3 01010001
V4 10000100
```
