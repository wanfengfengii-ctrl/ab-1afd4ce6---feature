# 扫描向量加载裁决 · 闭环全局排序 ＋ 备案顺序缓变加载

芯片量产测试时，多个扫描向量的加载需要遵守电源浪涌约束。本工具提供两种并存模式，
页面中录入/导入 **向量、每个引脚的整数浪涌权重、浪涌限额**，纯静态站点，无后端、无外部依赖：

1. **闭环加载顺序全局裁决**：完整比较全部 n! 条闭环顺序，先取全程翻转位数最小，
   并列按向量编号序列字典序取最小；
2. **缓变加载（已备案向量编号顺序）**：严格按录入顺序从全零出发并回零，每次正式跳转前
   插入仅用于切换的暂态（先统一降位，再把待置高引脚全局最优分组置高），
   完整比较全部分组与阶段顺序，先取暂态总数最少、并列按各阶段 P 序列字典序取最小。

## 问题模型

两种模式共享同一套输入：

- 向量数量 `4 ≤ n ≤ 12`，所有向量使用同一 `8–20` 位二进制掩码（自左向右为 `P1 … Pk`）；
- 设备从 **全零安全态** 出发；一跳的浪涌 = 该跳中 **由 0 变 1** 的引脚权重之和
  （1→0 不计浪涌，保持 1 不重复计费），要求每次置高浪涌 `≤ 限额`。

### 模式一：闭环全局裁决

- 每个向量恰好执行一次，最后 **回到全零态**，顺序由全局裁决决定；
- 裁决规则（两级，全局）：
  1. 先取 **全程翻转位数**（0→1 与 1→0 都算翻转，含收尾回零跳）最小的闭环顺序；
  2. 翻转位数并列时，取 **向量编号序列字典序**（编号字符串码点序，故 `10 < 2`）最小者；
- **禁止以逐跳最小翻转（贪心）替代全局裁决。**

算法为子集动态规划（Held–Karp 形态，`dp[S][i]`），精确等价于 n! 全排列穷举；
n=12 时约 4.9 万状态，数百毫秒完成；页面同时汇报 **闭环顺序总数 n!** 与
**满足逐跳浪涌约束的顺序数**（BigInt 精确计数）。
测试中另用一份完全独立的 n! 暴力枚举（300 组随机用例）对拍可行性、可行数、最优翻转与字典序。

### 模式二：缓变加载（备案顺序）

量产设备有时必须遵循 **已备案的向量编号顺序**（即当前录入顺序，不做任何重排）：
从全零出发，按录入顺序执行，最终回零；**每个正式向量仍在其原掩码处采样**。

每次正式跳转前允许插入仅用于切换的暂态：

1. **先一次性完成全部降位**（前掩码 1→0 的引脚全部落下），到达“前后掩码交集”暂态；
2. **再把全部待置高引脚（0→1）分组**，每组在一个切换阶段内同时置高；
3. 每个置高组必须同时满足：
   - 组内引脚 **权重和 ≤ 浪涌限额**（既有限额，模式一同一个）；
   - 组内 **引脚数 ≤ 每阶段置高引脚数上限**（新参数 `MAXRISE`，1–引脚数）。

降位不产生浪涌、也不计入置高引脚数。

裁决规则（两级，全局，**禁止逐引脚试探或贪心装箱**）：

1. 先取 **全程插入暂态总数最少** 的方案
   （Σ 各正式跳“降位态（有降位时 1 个）＋ 置高组数” ＋ 收尾回零的 1 个降位态）；
2. 暂态总数并列时，按 **各阶段置高引脚的 P 序列字典序** 取最小：
   所有置高阶段按时间先后排列，逐阶段比较升序 P 编号序列（`[P1,P3] < [P1,P4] < [P2]`）。

算法：对每一跳的待置高引脚集合，按 P 序列字典序生成全部“可行块”
（引脚数 ≤ 上限、权重和 ≤ 限额的非空子集），记忆化搜索“恰好 g 个有序块”的
字典序首个完整划分，并以 bin-packing 下界（`max(ceil(引脚数/上限), ceil(权重和/限额))`）
做可行性剪枝；顶层从最少组数下界起逐档裁决，首个成功档位即最少暂态方案。
测试用一份完全独立的 **有序集合划分（Fubini 数）全枚举** 暴力实现（1200 组随机用例）
对拍可行性、最少阶段数与 P 序列字典序，并覆盖 k=20 规模与稳定决胜专项。

**失败定位**：

- 某跳存在 **单个引脚权重 > 浪涌限额**：该引脚即使独占一组也越限，报告引脚与权重、
  所属正式向量（录入行号）、前后掩码；
- **约束下无法分组**：完整枚举全部可行组与全部阶段顺序后仍无法覆盖全部待置高引脚，
  报告无法被任何可行组覆盖的引脚与处置建议。

任一编辑（向量、权重、限额、位数、置高上限、模式切换）都会 **立即撤下旧报告**，
在途的计算结果自动作废。

## 页面功能

- 模式单选切换：闭环全局裁决 / 缓变加载；
- 掩码位数、限额、每阶段置高引脚数上限（仅缓变模式）、每个引脚权重、各向量编号/掩码的表格录入；
- 文本导入/导出（`PINS` / `LIMIT` / `W`(或 `WEIGHTS`) / 可选 `MAXRISE` /
  `编号 掩码`，支持 `#` 注释），导入错误按 **源文件行号** 定位；录入错误定位到具体向量行/引脚；
- 闭环模式：逐跳展示 **前掩码、后掩码、置高引脚（0→1，含权重）、浪涌/限额、本跳翻转、累计翻转**；
  无解时给出卡点诊断（哪些向量首跳即超限、哪些没有任何可行入边）；
- 缓变模式：按正式跳转展开 **切换前采样掩码 → 统一降位暂态 → 各置高组暂态 →
  原掩码处正式采样**，逐阶段展示暂态掩码、置高引脚、浪涌/限额、引脚数/上限、
  是否采样点与累计暂态数，并单列收尾回零跳；无法规划时逐跳定位失败原因。

## 本地运行（无需 Docker）

任意静态服务器即可，例如：

```bash
npx serve .                # 或：python3 -m http.server 8080
# 打开 http://localhost:8080
```

## Docker / Docker Compose

```bash
# 构建并启动（宿主机端口可用 WEB_PORT 配置，默认 8080）
WEB_PORT=9090 docker compose up --build -d
# 健康检查：容器内 wget /healthz；编排据 healthcheck 判定 web 健康
curl http://localhost:9090/healthz      # -> ok

# verify 服务：代码测试 + 构建检查 + HTTP 冒烟，自行退出，退出码即结论
docker compose run --rm verify

# 一条命令：起站、跑 verify、verify 结束后整体退出并透传其退出码
docker compose up --build --abort-on-container-exit --exit-code-from verify
```

`verify` 服务依次执行：

1. `node --test test/solver.test.mjs test/ramping.test.mjs`
   —— 闭环单元测试 + 300 组 n! 暴力对拍 + n=12 规模 + 反贪费用例；
   缓变单元测试 + 1200 组 Fubini 全枚举对拍 + k=20 规模 + 稳定决胜/失败定位/导入往返；
2. `node scripts/build-check.mjs` —— 文件齐备性、JS 语法检查、资源引用、两种模式端到端求解；
3. `BASE_URL=http://web:80 node test/smoke.mjs` —— 针对运行中容器的 HTTP 冒烟（12 项）。

全部通过退出码 `0`，任一失败非 `0`。

## 不使用 Docker 时的校验命令

```bash
node --test test/solver.test.mjs test/ramping.test.mjs  # 两套代码测试（需 Node >= 20）
node scripts/build-check.mjs                            # 构建检查
BASE_URL=http://localhost:8080 node test/smoke.mjs
node scripts/find-greedy-trap.mjs                       # 重新搜索“贪心 != 全局最优”的固化用例
```

## 导入文件格式

```
# 注释
PINS 8
LIMIT 6
W 2 1 3 1 2 1 1 1        # P1..P8 的浪涌权重（也可写作 WEIGHTS）
MAXRISE 2                # 可选：缓变加载每阶段最多同时置高的引脚数
V1 00101010
V2 11000001
V3 01010001
V4 10000100
```

`MAXRISE` 缺省时闭环模式不受影响；缓变模式在页面上单独填写/校验该上限。
